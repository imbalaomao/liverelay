# LiveRelay 自动直播转发工具 — 设计文档（规格说明）

- **日期**：2026-08-19
- **状态**：已通过头脑风暴评审，待用户终审
- **技术栈**：Wails v2（Go 后端 + WebView2 前端，Vue 3 + Tailwind CSS）

---

## 1. 项目概述

LiveRelay 是一款 Windows 桌面自动直播转发工具：调用 streamlink / streamlink-drm / yt-dlp 等外部工具抓取直播流，经 ffmpeg 无损转发（`-c copy`）至一个或多个推流目标（RTMP/RTMPS、SRT、UDP、本地 HLS），支持无人值守开播监控、同步本地录制、多路并发推流。

**设计红线（用户强制要求）：**

| 红线 | 工程答案 |
|------|---------|
| 坚决不允许内存溢出 | 所有流缓冲有界（OS 管道或 ≤8MB 环形缓冲），慢消费者降级丢弃，绝不堆积 |
| 坚决不允许 UI 注入 | WebView2 无 Node 集成、严格 CSP、默认转义、禁 `v-html`、子进程参数数组化 |
| 现代审美 UI | Clash for Windows 式侧边栏范式，Vue3 + Tailwind，深/浅双主题 |
| 小资源运行 | Go 核心常驻 <60MB；4 路 1080p 转发目标 <200MB / CPU <10%（i7-7700HQ + 8GB 实测验证） |

**目标运行环境基线**：Windows 10/11 x64，i7-7700HQ @2.8GHz，8GB DDR4，SATA SSD。WebView2 Runtime（Win11 自带；Win10 检测后引导安装）。

## 3. 总体架构

单进程 Wails 应用。Go 核心负责进程守护、管道装配、状态机、配置、托盘、电源管理；UI 为打包内静态资源渲染于 WebView2，经 Wails IPC 与 Go 通信。流数据不经过 Go 堆（默认走 OS 管道）。

```
┌──────────── 单进程 Wails 应用 ────────────┐
│  WebView2 UI ◄═Wails IPC═► Go 核心        │
│    ├ TaskManager     任务调度/状态机       │
│    ├ StreamPipeline  管道装配/缓冲池       │
│    ├ MonitorService  无人值守探测          │
│    ├ ToolManager     内核注册/版本/校验    │
│    ├ Updater         内核检查更新/下载     │
│    ├ ConfigStore     配置读写/备份         │
│    ├ TrayService     托盘                 │
│    └ PowerManager    防睡眠               │
└──────────────────┬───────────────────────┘
                   │ os/exec（参数数组，无 shell）
        ┌──────────┼──────────┐
        ▼          ▼          ▼
   streamlink   yt-dlp     ffmpeg（每任务 1 个）
   （每源 1 个）（每源 1 个）
```

**模块职责与接口（每个模块可独立测试）：**

- `TaskManager`：任务 CRUD、启动/停止、状态机推进、并发上限排队。接口：`Start(id) / Stop(id) / Status(id) / List()`
- `StreamPipeline`：按任务配置装配子进程管道，监督退出码，上报码率/时长统计。接口：`Build(task) → Pipeline / Run() / Abort()`
- `MonitorService`：无人值守探测循环。接口：`Watch(taskID) / Unwatch(taskID)`，探测结果回调 `TaskManager`
- `ToolManager`：内核注册表（内置 + 自定义），版本探测（`--version`）、路径校验、可执行性检查
- `Updater`：查询 streamlink / yt-dlp 最新版本，下载、校验、替换
- `ConfigStore`：JSON 单文件 + `.bak` 备份 + 原子写入（写临时文件后 rename）
- `TrayService` / `PowerManager`：见 §11

## 4. 推流管道

### 4.1 协议矩阵（首版全量支持）

| 目标协议 | ffmpeg 输出 | 典型用途 |
|---------|------------|---------|
| RTMP/RTMPS | `-f flv rtmp://...` | B站、微博、YouTube Live（首版验证目标） |
| SRT | `-f mpegts srt://...` | 自建低延迟中继服务器（后续） |
| UDP | `-f mpegts udp://...` | 内网组播/单播 |
| 本地 HLS | `-f hls -hls_time 4 -hls_list_size 6 <dir>/index.m3u8` | 本机/局域网直接观看 |

ffmpeg 以 `-c copy` 无损转发，不做转码（CPU 占用趋近零）。转码参数面板不在首版范围（YAGNI），但任务结构体预留 `TranscodeProfile` 字段。

### 4.2 双管道模式

**模式一：直通管道（默认）** — 一源 → 一/多目标

```
<抓流工具> <args> -O/输出到stdout ──► ffmpeg -i pipe:0 -c copy \
    -f flv <目标1> -f flv <目标2> [-f mpegts srt://...] [-f segment 录制]
```

- 一路源仅 1 个抓流进程 + 1 个 ffmpeg；多目标由 ffmpeg 多路输出复用，不重复抓流
- tee 复用优先使用 ffmpeg 多输出参数；若遇个别 muxer 组合兼容问题，回退为 tee muxer（`-f tee "out1|out2"`）

**模式二：Go 中继管道** — 仅当不同目标需要不同封装/转码参数时

```
抓流进程 ──► Go 有界环形缓冲（每源 ≤8MB）──► N 个 ffmpeg 子进程
```

- `sync.Pool` 复用 32KB 分块；环形缓冲满时**丢弃最旧分块**并标记该路"落后（lagging）"，UI 提示
- 硬性背压：任何消费者不得阻塞生产者；缓冲永不扩容 —— 内存溢出在机制上不可能发生

### 4.3 录制

- 任务级两个控制项：**"开始录制"按钮**（推流中随时手动启停）+ **"自动录制"开关**（任务开始推流即录制）
- 默认实现（ffmpeg 录制）：ffmpeg 增加一路 `-f segment -segment_time 1800 -strftime 1 recordings/<任务名>/%Y%m%d_%H%M%S.mp4`（30 分钟分段，防止单文件过大/掉电全损）
- 任务名用作目录名前必须做路径消毒：仅保留中英文、数字、`-` `_`，其余字符替换为 `_`，长度截断 64 字符；消毒后为空则回退用任务 ID
- **录制内核（可选）**：任务可改为绑定"录制内核"型自定义工具（如 N_m3u8DL-RE）。此时录制不经 ffmpeg segment，而是由该工具自身完成拉流/解密/落盘：
  - 录制内核与抓流推流**相互独立**：推流仍走 §4.2 管道；录制是并行启动的另一个子进程
  - 录制内核的参数模板与自定义参数按 §7.2 / §4.7 规则渲染与传递，输出路径以 `{outdir}` 占位符注入（指向该任务的录制目录）
  - 停止录制 = 向录制子进程发送终止信号并等待其写完文件尾
- 录制目录：便携模式 `<exe>/data/recordings/`，安装模式 `%APPDATA%/LiveRelay/recordings/`，可在设置中改

### 4.4 无人值守（MonitorService）

- 每任务一个"无人值守"开关。开启后：
  1. 用该任务绑定的工具做**轻量开播探测**（streamlink：`streamlink <url> --json`（不解码流）/ yt-dlp：`yt-dlp --dump-json --no-download`），间隔默认 60s（可配 30–300s）
  2. 探测到开播 → 通知 TaskManager 启动任务；下播（流正常结束）→ 停止任务，回到监控循环
- 多任务探测**时间错开 + 单 flight 合并**，避免瞬时并发请求
- 关闭"无人值守"则完全手动：UI 上"开始/停止"按钮控制
- 断流自动重连与无人值守正交：推流中异常断开 → 指数退避重连（2s 起步，封顶 60s，最大次数可配，默认无限）；正常下播不触发重连

### 4.5 并发上限

全局最大同时推流任务数（默认 4，可配 1–16）。超限时新任务进入"排队中"状态，有槽位自动启动。保护 8GB 内存目标机。

### 4.6 任务状态机

```
[空闲] ─开始(手动/无人值守/排队轮转)─► [启动中] ──► [推流中] ─停止/下播─► [空闲]
                                        │             │
                                        │         异常断开│
                                        ▼             ▼
                            [失败] ◄─退避耗尽─ [重连中] ◄─┘
                             │
                             └─(无人值守任务失败后回到监控循环)
```

排队状态：`[排队中]`，位于"空闲"与"启动中"之间。

### 4.7 自定义参数（绑定自定义内核的任务）

- 任务绑定**自定义内核**（抓流型或录制型）时，表单开放"自定义参数"输入框；绑定内置内核时不显示该字段（内置参数模板已固化，防止误改）
- 传递规则：输入字符串经**引号感知分词**（支持双引号/单引号包裹含空格参数，反斜杠转义）切为参数数组，**逐字追加**到内核参数模板渲染结果之后；全程无 shell 拼接
- UI 提供"预览完整命令"折叠区：显示模板渲染 + 自定义参数合并后的最终参数数组（密钥脱敏），便于用户核对"完整无误"

### 5.1 布局范式（参考 Clash for Windows）

左侧窄边栏导航 + 右侧内容区，三页面：**任务 / 内核 / 设置**。窗口无原生标题栏，自绘最小化/最大化/关闭（关闭按钮行为由"关闭到托盘"设置决定）。

│ ◈ 内核    │ ┌────────────────────────────────────┐ │

### 5.2 任务卡片

- 状态徽章（推流中/空闲/重连中/排队中/失败/无人值守探测中）
- 实时指标：画质、码率、已推时长、重连次数、录制状态
- 操作：开始/停止、编辑、删除、开始/停止录制
- 任务编辑表单字段：名称、直播源 URL、绑定抓流工具（下拉，含自定义）、画质（best/1080p/720p/worst 或自定义 streamlink 画质串）、推流目标列表（每条：协议 + 地址 + 密钥，可多条）、无人值守开关 + 探测间隔、自动录制开关、录制内核（可选，默认 ffmpeg 分段）、自定义参数（仅绑定自定义内核时显示，见 §4.7）

### 5.3 内核页

列表展示每个工具：名称、**当前生效的二进制路径及其版本号**（如 `streamlink 7.1.3`）、来源（内置/自定义）、角色（抓流/录制/两者）、功能探测摘要、状态（可用/缺失/版本探测失败）。

- 内置工具（streamlink / yt-dlp / ffmpeg）：显示默认 `tools/` 路径；提供"**使用本地二进制**"操作覆盖为任意本地 exe（条目本身仍不可删除，覆盖后提供"恢复默认"）
- 自定义工具：添加 / 编辑 / 删除（删除前校验无任务引用）
- 每个工具卡片显示**版本与功能探测结果**（首次添加/覆盖路径时自动运行 `--version` 与 `--help` 探测，见 §7.2），并提供"重新探测"按钮
- 内置工具提供：检查更新、下载/更新（仅对 `tools/` 下受管二进制生效；被覆盖为本地路径时更新器只提示不动手）

### 5.4 设置页

代理（见 §8）、并发上限、关闭到托盘、推流防睡眠、录制目录、探测默认间隔、主题（深/浅）、便携模式状态展示、日志目录打开。

### 5.5 视觉语言

- 深/浅双主题；深色为默认（直播工具场景）
- 8px 栅格、圆角 8/12px、单层阴影、毛玻璃侧栏
- 状态色：运行绿 / 警告橙 / 失败红 / 空闲灰，色彩对比度满足 WCAG AA
- 微动效 ≤200ms，禁用大幅动画（资源红线）
- 前端技术：Vue 3（Composition API）+ Tailwind CSS + 自绘组件，不引入重型 UI 库

## 6. 配置与存储

### 6.1 双模式判定

启动时按顺序判定：

1. exe 同级存在 `data/` 目录 → **便携模式**，一切存 `data/`
2. 否则 → **安装模式**，存 `%APPDATA%/LiveRelay/`（首次运行自动创建）

设置页显示当前模式；提供"转为便携"按钮（在 exe 旁创建 data/ 并迁移配置，下次启动生效）。

### 6.2 目录结构

```
<数据根>/  (便携: <exe>/data | 安装: %APPDATA%/LiveRelay)
├── config.json        # 全部配置（任务、工具、设置），原子写入 + .bak
├── tools/             # 内置内核：streamlink.exe、yt-dlp.exe、ffmpeg.exe
│                      # （streamlink-drm.exe 由用户提供后放入或指定路径）
├── logs/              # 滚动日志 3×2MB + 每任务最近输出
├── recordings/        # 录制文件（可在设置中改到其他目录）
└── cache/             # 更新下载临时文件
```

### 6.3 卸载

安装模式提供卸载入口：向导中勾选"同时删除配置与数据" → 删除 `%APPDATA%/LiveRelay` 整个目录。便携模式零注册表写入，删除目录即完成卸载。

### 6.4 config.json 顶层结构

```json
{
  "version": 1,
  "settings": { "proxy": {}, "maxConcurrent": 4, "closeToTray": true,
                "preventSleep": true, "theme": "dark",
                "recordDir": "", "probeIntervalSec": 60 },
  "tools": [ { "id": "streamlink", "builtin": true, "path": "tools/streamlink.exe",
               "pathOverride": "", "version": "7.1.3", "capSummary": "",
               "role": "fetch" } ],
  "tasks": [ { "id": "uuid", "name": "...", "sourceUrl": "...",
               "toolId": "streamlink", "quality": "best",
               "targets": [ { "proto": "rtmp", "url": "...", "key": "..." } ],
               "unattended": false, "autoRecord": false,
               "recordToolId": "", "customArgs": "" } ]
}
```

推流密钥（key）默认在 UI 掩码显示；v1 明文存 JSON（文件权限为用户目录），`TranscodeProfile` 与密钥加密存储（Windows DPAPI）列为 v1.1 增强项。

## 7. 内核管理（ToolManager + Updater）

### 7.1 内置工具（不可删除，可覆盖路径）

`streamlink`、`yt-dlp`、`ffmpeg` 三个内置条目固定存在、不可删除、参数模板不可编辑。默认使用 `tools/` 目录下随包/受管的二进制；用户可在设置/内核页**覆盖为本地 exe**（覆盖记录于 `pathOverride`），并可一键"恢复默认"。版本号始终按当前生效路径探测显示。

### 7.2 自定义工具与能力探测

- 手动添加：名称 + exe 路径 + **角色**（抓流内核：stdout 出流接 ffmpeg 管道 / 录制内核：自行拉流解密落盘，如 N_m3u8DL-RE / 两者皆可）+ 参数模板（占位符 `{url}` `{quality}` `{proxy}` `{outdir}`）+ 探测命令模板
- 典型用例：用户提供的 `streamlink-drm.exe`（抓流/两者）；`N_m3u8DL-RE.exe`（录制内核）
- **首次添加/覆盖路径时的自动能力探测**：
  1. 依次尝试 `--version`、`-V`、`version`，首个成功输出解析为版本号（正则提取 `\d+\.\d+[\d.]*`）
  2. 运行 `--help`（失败回退 `-h`），解析输出中生成功能摘要：支持的协议/参数开关清单（截断展示前 N 条），原始输出存日志供查看
  3. 探测超时 10s、输出上限 1MB（防恶意/异常二进制拖死 UI）；探测失败不阻止添加，标记"版本未知/功能未探测"
- 可编辑、可删除；删除前校验无任务引用，有引用则禁止并提示

### 7.3 更新器

- streamlink：查询 GitHub Releases（`streamlink/streamlink` Windows 构建）
- yt-dlp：查询 GitHub Releases（`yt-dlp/yt-dlp`，`yt-dlp.exe`）
- 流程：检查版本 → 用户确认 → 下载（走全局代理）→ SHA256 校验（从 release 的校验文件读取）→ 替换（旧文件备份为 `.old`，失败自动回滚）
- 仅作用于 `tools/` 下受管二进制；路径被用户覆盖为本地 exe 的内置工具，更新器显示提示但不执行替换
- 下载进度在 UI 可见；同时仅允许一个更新任务

## 8. 代理

- 设置项：类型（HTTP / SOCKS5）+ 主机 + 端口 + 可选用户名密码
- 启用后传递给所有组件：
  - streamlink / streamlink-drm：`--http-proxy` `--https-proxy`
  - yt-dlp：`--proxy`
  - ffmpeg：`http_proxy` / `https_proxy` 环境变量
  - Updater（Go HTTP Client）：`http.Transport.Proxy`
- 自定义工具的参数模板中以 `{proxy}` 占位符注入
- 提供"测试连接"按钮（请求 https://www.google.com/generate_204 与 GitHub API 各一次，显示延迟）

## 9. 资源策略（红线保障）

| 项 | 策略 |
|----|------|
| 流缓冲 | 默认 OS 管道零拷贝；Go 中继模式每源 ≤8MB 环形缓冲，满则丢最旧块 + 标记落后 |
| 日志 | 内存中每任务最近 500 行；磁盘滚动 3×2MB |
| UI 事件 | 状态推送 250ms 节流合并；WebView 端列表虚拟滚动（任务 >100 时） |
| 对象复用 | 32KB 分块 `sync.Pool`；禁止每帧分配 |
| goroutine | 每任务固定 3 个（监督/统计/探测），禁止无界 spawn；退出全走 context 取消 |
| 磁盘 | 录制分段 30min；cache/ 更新完成后清理 |

**验收指标（目标机 i7-7700HQ/8GB 实测）**：空载内存 <60MB、CPU <1%；4 路 1080p（各 ~6Mbps）转发内存 <200MB、CPU <10%。

## 10. 安全策略（XSS / 注入防线）

1. WebView2 无 Node 集成、无远程内容，仅加载打包内资源
2. CSP：`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:`；禁 `eval` / inline script
3. 用户输入渲染：Vue 模板默认转义；全项目禁 `v-html`
4. 子进程调用一律 `exec.Command(name, args...)` 参数数组，**无 shell 拼接**；自定义参数经 §4.7 引号感知分词后同样以数组元素逐字传递；URL 与密钥不经命令行回显日志（日志中密钥脱敏为 `***`）
5. 推流密钥 UI 掩码显示；config.json 权限限定当前用户
6. 更新下载强制 SHA256 校验 + HTTPS

## 11. 系统集成

### 11.1 托盘

- "关闭到托盘"开启（默认）：点关闭按钮仅隐藏窗口，Go 核心与全部推流任务继续运行
- 托盘图标：左键还原窗口；右键菜单：显示主界面 / 推流概况（N 路推流中）/ 退出（二次确认，有任务运行时提示"N 个任务将被停止"）

### 11.2 防睡眠

- "推流时保持电脑不睡眠"开启（默认）：存在运行中任务时调用 `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)`；全部任务停止或程序退出时恢复 `ES_CONTINUOUS`
- 仅阻止系统睡眠，不阻止屏幕关闭
